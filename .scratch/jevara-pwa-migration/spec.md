# JEVARA — PWA Offline-First + Supabase Sync → Vercel (Next.js + Tailwind + shadcn + TypeScript)

## Problem Statement

JEVARA saat ini hidup sebagai monolit `index.html` (~558KB, 2800+ baris JS inline, 315 baris CSS inline) yang disimpan 100% di `localStorage` (`gym_v6`, `gym_iqbal_premium_v3`, `jevara_commercial_beta_091`, `jevara_beta_account_v1`). Hosting masih di Cloudflare Workers (`deploy/wrangler.toml`) sebagai static asset, tanpa backend, tanpa multi-device, dan tanpa migrasi data yang aman. User yang latihan di gym dengan sinyal buruk tetap bisa log, tapi data tidak pernah keluar dari satu device — hilang kalau browser di-clear, tidak bisa lanjut di HP lain, dan tidak ada sumber kebenaran tunggal. JEVARA IQ (`je099cIQ`/`iqLite`) hanya membaca `premium.events` lokal, `weeklyMuscles` dan `PR` hanya dari `localStorage`, sehingga semua progress tidak portable. Migrasi ke stack modern harus dilakukan tanpa mengubah arsitektur dan sistem (istilah `Set/Session/Event/Exposure/Readiness/e1RM/Baseline/PR/CALIBRATE/HOLD/BUILD_*` di `CONTEXT.md` dan canonical `RC4` di `docs/adr/0002` harus tetap identik).

## Solution

Bangun ulang JEVARA sebagai **Progressive Web App offline-first** di **Vercel** dengan **Next.js App Router + TypeScript + Tailwind + shadcn/ui**, **Supabase** (Auth + Postgres) sebagai replica yang di-sync via **SyncQueue + Service Worker backgroundSync**. `IndexedDB` (fallback `localStorage`) tetap menjadi source-of-truth lokal — setiap `Set` yang ditandai Done, setiap `Session` yang di-FINISH, dan setiap `Readiness` yang disimpan langsung menulis lokal dulu, lalu enqueue ke outbox untuk replikasi ke Supabase saat online. **Canonical Record** (`sessions` RC4) tetap menjadi satu-satunya kebenaran untuk History, Progress, dan JEVARA IQ; `premium.events` tetap ledger audit. PWA mempertahankan `manifest.webmanifest` + `sw.js` network-first untuk document dan cache-first untuk static, ditambah install prompt dan update flow. Tidak ada perubahan pada hierarki `Foundation / Template Program / Custom Program / Sesi Terencana` atau mesin IQ.

## User Stories

1. As a gym member, I want to install JEVARA ke home screen via PWA install prompt, so that saya bisa buka seperti aplikasi native tanpa buka browser.
2. As a gym member, I want to membuka JEVARA saat offline dan tetap melihat Sesi Terencana hari ini (Foundation atau Template Program), so that latihan tidak tergantung sinyal.
3. As a gym member, I want to mencatat Set (kg, reps, RIR, type) dan menandai Done saat offline, so that tidak kehilangan data di basement gym.
4. As a gym member, I want to memulai Session (START) offline dan melihat timer durasi berjalan, so that durasi tetap tercatat lokal.
5. As a gym member, I want to menyelesaikan Session (FINISH) offline dan mendapat Canonical Record `completed` atau `ended_early`, so that sesi tetap final walau offline.
6. As a gym member, I want to data yang saya catat offline otomatis tersync ke Supabase saat online kembali tanpa klik manual, so that data tidak perlu diingat untuk di-upload.
7. As a gym member, I want to login di device kedua dan melihat History, Progress, dan PR yang sama setelah sync, so that bisa ganti HP tanpa kehilangan progres.
8. As a gym member, I want to akun beta lokal (guest/email) termigrasi ke Supabase Auth (email OTP) dengan RLS `user_id = auth.uid()`, so that data terisolasi per user.
9. As a gym member, I want to import backup JSON lama (`exportData` RC4) ke install baru dan tetap menjadi Canonical yang valid, so that tidak kehilangan 12 minggu Foundation yang sudah dijalani.
10. As a gym member, I want to Foundation 12 minggu (3 Fase, 5 hari/minggu, `curPh/curWk/curDay`) tetap navigable dengan pill yang sama, so that tidak perlu belajar ulang.
11. As a gym member, I want to memilih Template Program (rc1/fl1/bu1/st1/hp1/mn1) dan melihat detail sesi sebelum mulai, so that bisa ganti tujuan (rekomposisi/cutting/bulking) tanpa ubah sistem.
12. As a gym member, I want to membuat Custom Program via Program Builder dan memulainya sebagai `activeCP` yang masuk mesin logging yang sama, so that program buatan sendiri diperlakukan setara Foundation.
13. As a gym member, I want to Sesi Terencana menampilkan `expectedSets` yang benar untuk hari itu, so that FINISH tahu apakah `completed` atau `ended_early`.
14. As a gym member, I want to melihat JEVARA IQ memberi status CALIBRATE saat Exposure <3, so that tidak disuruh naik beban terlalu cepat.
15. As a gym member, I want to melihat JEVARA IQ HOLD saat baseline ada tapi belum konsisten, so that tahu harus kejar reps dulu.
16. As a gym member, I want to melihat JEVARA IQ BUILD_REPS saat beban pas, so that tahu harus tambah repetisi dulu.
17. As a gym member, I want to melihat JEVARA IQ BUILD_LOAD hanya saat reps>=max, RIR>=2, Exposure>=3, dan Readiness>=60, so that kenaikan 1–2.5kg aman.
18. As a gym member, I want to melihat JEVARA IQ RECOVER saat Readiness <50, so that progression ditunda hari itu tanpa diagnosis medis.
19. As a gym member, I want to e1RM hanya dihitung untuk compound eligible (bench/squat/deadlift/row, bukan isolasi), so that PR isolasi memakai best_set `kg×reps` yang jujur.
20. As a gym member, I want to melihat PR hanya muncul setelah Baseline (`baseline:true` pertama) terkalahkan, so that minggu pertama tidak spam PR.
21. As a gym member, I want to mengisi Readiness (Energy/Sleep/Soreness 1–5) sebelum latihan dan melihat skor 0–100, so that ada konteks hari ini.
22. As a gym member, I want to melihat Recovery Status (LOW/WATCH/STABLE) sebagai output IQ, bukan input, so that tidak salah paham penyebab deload.
23. As a gym member, I want to deload tidak pernah dipicu oleh Readiness saja (butuh `je099cPersistentDecline` juga), so that tidak takut deload karena satu malam kurang tidur.
24. As a gym member, I want to rest timer otomatis (default 90s, `suggestedRest` per exercise) yang pause/adjust/skip dan survive refresh via persist `je099RestState`, so that istirahat tetap akurat.
25. As a gym member, I want to Session Autopilot memandu set-by-set dengan input kg/reps/RIR dan full-screen rest, so that tidak perlu cari exercise manual.
26. As a gym member, I want to swap exercise di Autopilot dengan alasan (equipment busy/too difficult) dan kandidat tetap hitung sebagai CALIBRATE tanpa copy beban, so that pengganti tidak mewarisi beban yang salah.
27. As a gym member, I want to melihat Previous Performance (`lastEventFor`) dan chart e1RM di History per exercise, so that bisa bandingkan progres.
28. As a gym member, I want to melihat Progress tab menampilkan phase bars, lift chart (Deadlift/Squat/Bench), weeklyMuscles, dan weight chart dari Canonical yang final saja, so that data tidak tercemar sesi yang belum finish.
29. As a gym member, I want to aplikasi mengingatkan update tersedia saat `sw.js` network-first mendeteksi build baru, so that tidak terjebak di build lama (bug `je1817-hotfix` sebelumnya).
30. As a gym member with bahasa Indonesia, I want to semua label, status IQ, dan recovery copy mengikuti `JE_LANG` tanpa hard-code campur, so that pengalaman konsisten.
31. As a gym member, I want to backup/restore tetap ada (Export JSON) tapi setelah online data juga ada di Supabase, so that clear browser tidak lagi fatal.
32. As a tester, I want to menekan FINISH dua kali tidak membuat dua Canonical Record, so that guard `FINALIZING` tetap idempotent di Supabase (`upsert` by `id`).
33. As a product owner, I want to hosting pindah dari Workers ke Vercel dengan redirect 301 agar `gymtracker.iqbal-nataprawira.workers.dev` tidak 404, so that beta tester lama tetap menemukan app.
34. As a product owner, I want to Tailwind memetakan token lama (`--bg:#080B12`, `--blue:#5DA8FF`) dan shadcn menggantikan card/pill/tabs tanpa ubah layout, so that visual tetap JEVARA.

## Implementation Decisions

- **Framework**: Next.js 14 App Router + TypeScript (strict) di Vercel. Alasan: native untuk Tailwind/shadcn, file-based routing untuk 5 tabs, dan `public/sw.js` + `public/manifest.webmanifest` tetap dilayani sebagai static (migrasi dari `deploy/public`). Tidak memakai Vite SPA demi SSR/SEO dan `next-pwa` integration. Sesuai `docs/adr/0003`.
- **Styling**: Tailwind CSS dengan token mapping dari `:root` lama (`--bg:#080B12`, `--bg2:#111622`, `--cyan:#5DA8FF` di `index.html:266`) ke `theme.extend.colors.jevara.*`. shadcn/ui untuk `Card`, `Tabs`, `Dialog` (overlay `ov:336`), `Toast` (`toast:345`), `Switch` (`settings-row:144`). Tidak ada perubahan visual, hanya ganti `<style>` inline 315 baris menjadi utility classes.
- **Modularisasi monolit 558KB**: `index.html` dipecah menjadi `app/layout.tsx` (hdr + tabs + overlay), `data/foundation.ts` (`D`), `data/programs.ts` (`PG` + `CATS`), `lib/types.ts` (union `SetType = 'N'|'W'|'D'|'F'|'T'|'B'`), `lib/e1rm.ts` (`calcE1RM`, `e1rmEligible`), `lib/muscle.ts` (`muscleFor`, `MUSCLE_MAP`), `lib/iq.ts` (`je099cIQ` → pure `iqLite` tanpa side-effect), `lib/readiness.ts` (`readinessScore`, `je095ReadinessAction`), `lib/session.ts` (`jeRC2SessionMeta`, `canonicalSnapshot`, `upsertSession`), `hooks/useAutopilot.ts` + `components/workout/Autopilot.tsx` (`JE095.autopilot`, `je096RestState`), `components/progress/*` (lift chart, phase bars, weight chart). Semua modul mempertahankan nama glossary `CONTEXT.md`.
- **Storage layer seam (seam tertinggi untuk test)**: Adapter `StoragePort { loadLog, saveLog, loadPremium, savePremium }` yang sekarang membungkus `localStorage` (`gym_v6`/`gym_iqbal_premium_v3`) diganti menjadi `IndexedDBPort` (via `idb-keyval`) dengan fallback localStorage untuk migrasi. `premium.events[500]`, `sessions[150]`, `readiness[60]` tetap dibatasi sama. Seams lama (`loadLog:590`, `dedupePremiumEvents:1237`) dipertahankan sebagai contract.
- **Supabase schema**: 6 tabel sesuai ADR 0001 — `profiles(id uuid FK auth.users)`, `workout_logs(user_id, key text, kg, reps, rir, type, ok, session_id, updated_at, UNIQUE(user_id,key))`, `premium_events(user_id, session_id, key, name, kg, reps, rir, type, volume, ts)`, `sessions(id text PK, user_id, canonical_version, state, label, expected_sets, completed_sets, volume, duration, started_at, ended_at, exercise_summary jsonb)`, `readiness(user_id, date_key text PK, energy, sleep, soreness, score, ts)`, `custom_programs(id text PK, user_id, title, ex jsonb)`. RLS: `USING (auth.uid() = user_id)` untuk semua tabel. Migrasi awal: import `exportData:1552` JSON → `upsert` batch. Conflict `premium.events` dedupe `seen[sessionId::key]` dipertahankan server-side via `ON CONFLICT (user_id,key) DO UPDATE`.
- **Auth**: Ganti `AUTH_KEY` lokal (`authGet:352`) menjadi Supabase Auth (email OTP + anon `guest` via `supabase.auth.signInAnonymously()` untuk kompatibilitas `type:'guest'`). `LANG_KEY` dan onboarding `je098StartOnboarding:447` tetap lokal, `profile` di-`upsert` ke `profiles` setelah onboarding. `authMask` tetap untuk display.
- **Offline-first sync (ADR 0001)**: Setiap `je095SaveInput:849` dan `onSetCompleted:1261` tulis ke IndexedDB dulu → enqueue `outbox` (IndexedDB `sync_queue` table: `{table, op, payload, ts}`) → Service Worker `backgroundSync` atau `navigator.onLine` listener flush via `supabase.from(table).upsert()` dengan `last-write-wins` per `(sessionId,key)` — sama seperti `dedupePremiumEvents`. Tidak ada blocking UI; `showSv("Tersimpan")` tetap lokal. Device kedua hydrate via `select * where user_id = auth.uid()` sekali saat login, lalu offline.
- **Canonical Record contract (ADR 0002)**: `finishWorkout:2611` tetap idempotent (`FINALIZING[sid]` guard) → `canonicalSnapshot` → `sessions.upsert({id})` (PK `id` = `s+Date.now()`). `jeRC4FinalizedIds` dan `weeklyMuscles:2446` hanya query `sessions where state in ('completed','ended_early') and canonical_version='RC4'`. `updatePR:2632` tetap `baseline:true` pertama, `baseline:false` saat `metric > old.bestMetric`. Tidak ada double Canonical saat FINISH ditekan dua kali.
- **PWA**: `next-pwa` + Workbox (`skipWaiting`, `clientsClaim` sudah ada di `sw.js:8`) — precache `_next/static`, `icon-192/512.png`, `manifest`. `runtimeCaching`: `NetworkFirst` untuk `document` (`/` dan `/index.html` sesuai `sw.js:34`), `CacheFirst` untuk `icon/manifest`, `NetworkOnly` untuk `supabase.co/rest/v1/*` dan `supabase.co/auth/v1/*` (jangan cache auth). Tambah `usePWAInstall` hook untuk `beforeinstallprompt` di Tools tab dan `UpdateBanner` saat `sw.js` detect new `CACHE`.
- **i18n**: `I18N:359` + `JE_LANG` (`jevara_language_v1`) tetap localStorage, komponen menerima `t(k)` helper. Tidak ada hard-code string campur setelah `rc3.1` fixes.
- **Deployment**: Vercel project `jevara` (atau `gymtracker`), env `NEXT_PUBLIC_SUPABASE_URL` + `NEXT_PUBLIC_SUPABASE_ANON_KEY` (client), `SUPABASE_SERVICE_ROLE` hanya di build/migration. `deploy/wrangler.toml` disusutkan menjadi redirect 301 `workers.dev/*` → `jevara.vercel.app/*`. Domain custom via Vercel Domains. `vercel.json` tidak perlu `not_found_handling = single-page-application` — Next.js handle via `app` routing.
- **Type shapes (dari prototype analisis index.html)**: `type CanonicalSession { id: string; canonicalVersion: 'RC4'; state: 'active'|'finishing'|'completed'|'ended_early'; label: string; plannedSessionId: string; contextSig: string; expectedSets: number; completedSets: number; volume: number; duration: number; startedAt: number; endedAt?: number }`, `type PremiumEvent { sessionId: string|null; key: string; name: string; exerciseId: string; kg: number; reps: number; rir: number|null; type: 'N'|'W'|'D'|'F'|'T'|'B'; volume: number; ts: number; measurementType?: string }`. Shapes ini mengkode keputusan ADR 0002 lebih presisi daripada prose.

## Testing Decisions

- **Filosofi test**: Hanya test perilaku eksternal di seam, bukan detail implementasi. Satu Set yang di-Done harus muncul di History dan mengubah weeklyMuscles; satu Session yang di-FINISH harus menjadi Canonical dan mengajar IQ — bagaimana IndexedDB vs Supabase di-sync di belakang layar tidak di-assert.
- **Seam tertinggi (satu seam, ideal)**: `Session seam` — `startWorkout() → je095Complete/onSetCompleted() → finishWorkout() → jeRC4FinalizedSessions()`. Test di seam ini otomatis cover storage, dedupe, canonical, dan IQ tanpa mock dalam. Ini preferensi utama; tidak perlu seam lebih rendah kalau high seam sudah hijau.
- **Seam yang dipertahankan**: `StoragePort` (IndexedDB vs Supabase outbox) — test dengan fake IndexedDB (`fake-indexeddb`) dan Supabase client di-mock di boundary `SyncQueue.flush()`. `IQ seam` (`iqLite(name,target)` pure function) — test table-driven: `Exposure 0→CALIBRATE`, `exposure 3 + reps>=max + RIR>=2 + readiness 70 → BUILD_LOAD`, `readiness 30 → HOLD` walau reps terpenuhi.
- **Seam baru (satu-satunya yang diusulkan)**: `SyncQueue` (outbox) — satu modul baru yang isolate network; test: enqueue saat offline → flush saat online → `supabase.upsert` dipanggil sekali per `(sessionId,key)` walau `onSetCompleted` dipanggil 3x (dedupe).
- **Modul yang akan di-test**: `lib/session` (canonical idempotency, `FINALIZING` guard, `ended_early` vs `completed`), `lib/storage` (migrasi `exportData` → IndexedDB → Supabase), `lib/iq` (semua 5 status + `e1rmEligible` branching), `hooks/useAutopilot` (swap tidak copy beban, CALIBRATE untuk pengganti), `components/progress` (hanya render dari `jeRC4FinalizedSessions`, bukan ledger mentah).
- **Prior art**: `docs/RELEASE NOTES beta1.md` sudah verifikasi via Node.js + jsdom end-to-end (normal flow, LATIH ULANG, Plank/bodyweight, swap, custom program, PR display) — test baru akan meniru pola yang sama dengan Vitest + jsdom + `@testing-library/react`, plus `msw` untuk mock Supabase REST. Tidak ada `undefined/NaN` bocor ke layar di semua skenario tersebut harus tetap hijau. Semua 51 blok `<script>` yang dulu lolos `Node --check` sekarang menjadi unit/integration test.
- **PWA test**: Playwright + Lighthouse CI (`pwa` category) — assert `manifest` valid, `sw.js` ter-register, `NetworkFirst` untuk document (bukan terjebak build lama), `CacheFirst` untuk ikon, dan `NetworkOnly` untuk Supabase.

## Out of Scope

- Perubahan arsitektur atau sistem: tidak ada perubahan hierarki `Foundation` 3 Fase, `PG` 6 Template, atau mesin IQ `e1RM` Epley. Hanya ganti wadah render dan storage.
- Push notification dan background periodic sync — PWA v1 hanya `backgroundSync` untuk workout_logs; notifikasi streak/re-engagement ditunda ke iterasi berikutnya.
- Multi-user collaboration / shared sessions — RLS `user_id` isolate, tidak ada `team` atau `coach` role.
- Pembayaran / entitlement `jevara.entitlement = BETA PRO` — tetap `local` (`jevara_commercial_beta_091`), tidak ada Stripe/Supabase billing di v1. `activateBeta` tetap simulasi.
- Kalkulator 1RM/Plate yang belum diuji di beta (`docs/RELEASE NOTES` "Belum Diuji") — tetap ada tapi tidak di-improve di spec ini.
- Migrasi data dari versi JEVARA sebelum `J1.18.34` — upgrade path lama tetap tidak di-cover (sudah "Belum Diuji").
- Analytics aggregate multi-user (`jevara.events[1000]` + `track()`) — tetap lokal; backend analytics privacy-aware ditunda.
- Percobaan ganti `supabase-js` dengan `Prisma` atau `Drizzle` — stay dengan `supabase-js` untuk RLS dan realtime.

## Further Notes

- Semua istilah di spec ini memakai glossary `CONTEXT.md` (Set/Session/Event/Exposure/Readiness/e1RM/Baseline/PR/CALIBRATE/…) dan menghormati `docs/adr/0001..0003`. Jika ada konflik dengan kode lama, `CONTEXT.md` menang — perbaiki kode, jangan perlebar glossary.
- Seams yang diusulkan (Session seam sebagai yang tertinggi, SyncQueue sebagai satu-satunya seam baru) perlu dikonfirmasi user sebelum implementasi — jika user ingin lebih sedikit seam, SyncQueue bisa dilipat ke StoragePort.
- Spec ini belum memuat path file atau snippet panjang; bentuk `CanonicalSession`/`PremiumEvent` di atas adalah satu-satunya snippet yang dipertahankan karena mengkode ADR 0002 lebih presisi daripada prose.
- Setelah spec ini di-`approve`, langkah berikutnya di main flow adalah `/to-tickets` (pecah menjadi 10 tiket tracer-bullet blockers-first) lalu `/implement` per tiket dengan `tdd` internal dan `code-review` dua sumbu sebelum commit.
